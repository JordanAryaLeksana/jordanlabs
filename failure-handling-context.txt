## 1. Ringkasan proyek

Portfolio website personal yang muka utamanya adalah interface chat AI full-screen. Chatbot bukan sekadar fitur di pojok — ia adalah lapisan interaksi utama yang mengendalikan seluruh situs: menjawab pertanyaan tentang pemilik (pengalaman, skill, hobi, proyek) dari knowledge base, dan bertindak lewat tool calling (pindah halaman, download CV, buka LinkedIn/GitHub, render kartu).

Situs punya DUA interface (rinci di §1a):

- Interface Chat (AI) — landing `/` berupa chat full-screen. Cara utama menjelajah.
- Interface Konten (tradisional) — halaman berdiri sendiri (`/about`, `/projects`, `/projects/[slug]`, `/research`, `/contact`) sebagai tujuan navigasi.

Prinsip produk: chat adalah lapisan interaksi utama, TAPI tidak boleh jadi penghalang. Info inti (nama, posisi, kontak, link CV) tetap terlihat ~20 detik tanpa mengetik lewat header statis ringkas yang di-render server pada landing — demi recruiter yang buru-buru dan demi SEO. Halaman konten tradisional selalu dapat diakses lewat navbar maupun perintah chat, sehingga pengunjung yang enggan mengetik tetap terlayani.

Tema visual proyek ini terinspirasi dari title sequence drama Korea "START-UP" (tvN). Yang diambil adalah bahasa visual flat-retro-nya (blok warna, geometri tegas, palet hangat), bukan reproduksi karyanya. Konteks ini penting untuk memahami arah estetika di §4-§6.

Fokus belajar pemilik: prioritas utama adalah mempelajari implementasi LLM (RAG, embedding, tool calling). Saat mengerjakan bagian §7, utamakan penjelasan yang mendidik — jelaskan alasan di balik keputusan, bukan sekadar memberi kode jadi.

## 1a. Halaman & isinya

Situs punya dua interface yang mengakses konten SAMA: Interface Chat (AI) dan Interface Konten (tradisional). Keduanya bisa dinavigasi — pengunjung bisa mengetik ke chatbot ATAU mengklik navbar/kartu. Karena itu tiap halaman punya route tetap dan tiap section punya `id` DOM stabil; keduanya jadi target yang bisa "dituju" tool navigasi (lihat §7, Kelompok A). Daftar route & section id di sini adalah sumber kebenaran yang dicerminkan di `lib/tools/types.ts`.

### Interface Chat — Landing (`/`)

Landing adalah chat full-screen, BUKAN halaman scroll. Terdiri dari dua bagian:

- Header statis ringkas (`StaticHeader`) — di-render server, selalu terlihat tanpa mengetik: nama (`KineticHeading`), posisi/tagline, tombol CV, tautan GitHub/LinkedIn, toggle tema, dan tautan ke halaman konten. Ini yang memenuhi syarat "info inti ~20 detik" dan menjadi konten yang diindeks SEO.
- Permukaan chat (`ChatWidget`) — area utama tempat percakapan dan generative UI (tool-cards) tampil. Sertakan sapaan pembuka + beberapa contoh pertanyaan (suggested prompts) agar pengunjung tahu chatbot bisa apa.

Chatbot berlaku di seluruh situs (site-wide): komponen kontrol chat dipasang di root layout (`ChatController`) sehingga tetap hidup saat pindah route. Di `/` ia tampil full-screen; di halaman konten ia menyusut jadi panel/dock yang bisa dibuka — sehingga chatbot tetap mengendalikan navigasi dari halaman mana pun.

### Interface Konten — Halaman terpisah

- `/about` — profil lengkap. Section: `about-background` (latar & cerita), `about-skills` (skill grid), `about-experience` (timeline pengalaman).
- `/projects` — daftar proyek. Section: `projects-featured` (unggulan: EMQNET, DermSight) dan `projects-all` (semua + filter, mencerminkan tool `filterProjects`).
- `/projects/[slug]` — detail proyek (`emqnet`, `dermsight`). Section: `overview`, `architecture`, `dataset`, `training`, `evaluation` (untuk jalur technical interviewer).
- `/research` — publikasi/riset. Section: `research-list`.
- `/contact` — kontak. Section: `contact-form` + contact card.

### Ringkasan target tool

- Route untuk `navigateToPage`: `/`, `/about`, `/projects`, `/research`, `/contact`, plus detail `/projects/emqnet` dan `/projects/dermsight`.
- Section id untuk `scrollToSection`/`highlightSection` (berada di halaman konten): `about-background`, `about-skills`, `about-experience`, `projects-featured`, `projects-all`, `research-list`, `contact-form`, plus section detail proyek (`overview`, `architecture`, `dataset`, `training`, `evaluation`).

Catatan: karena landing bukan halaman scroll, `scrollToSection` menyasar section di halaman konten. Bila chatbot perlu membawa pengunjung ke skill (mis. "show your skills"), alur normalnya dua tool berurutan: `navigateToPage('/about')` lalu `scrollToSection('about-skills')`, keduanya dijalankan client (§7a).

## 1b. Bahasa visual & motion tiap interface

Aspek desain ala-startup (§4-§6, §11) WAJIB hadir di kedua interface — landing chat tidak boleh terasa seperti kotak chat generik. Pakai kosakata komponen retro (§6/§6a) dan aturan motion (§11).

Landing (chat):

- Header: nama lewat `KineticHeading` (stagger huruf + underline SVG); aksen `ColorBlockBar`/`DiagonalStripes` sebagai dekorasi tegas, bukan ramai.
- Latar permukaan chat: motif retro tipis sebagai tekstur — mis. `HexGrid` sebagai alas bawah atau `DiagonalStripes` samar — digerakkan sangat lambat (ambient) lewat pergeseran blok warna aset, BUKAN gradient (§11).
- Pesan masuk: fade + translate dengan stagger (§11). Tool-cards (`CvCard`, `ContactCard`, Project Cards, Skill Grid) muncul dengan animasi signature color-block reveal (§11), dipakai terbatas agar tetap bermakna.
- Suggested prompts sebagai `Pill`/`Badge` atau `SplitCard` kecil.

Halaman konten:

- Bungkus tiap section dengan `Section` + scroll reveal konsisten (§11). Motif retro dipakai sesuai §6a: `SplitCard` untuk tag proyek, `NestedFrame` untuk item terpilih, `PreviewCard` untuk thumbnail.
- `highlightSection` memakai `NestedFrame`/`frame-green` untuk menandai section yang sedang disorot chatbot.

Transisi antar-interface (landing <-> halaman konten):

- Gunakan wipe sinematik color-block / clip-path (§11 signature), bukan hilang mendadak. Karena `ChatController` persist di root layout, chat tidak ikut ter-unmount saat wipe.
- Intro sequence (§11, Loading screen) keluar via wipe menuju landing chat ini, bukan ke halaman scroll.

Semua tetap tunduk §3 (siku, tanpa gradient/blur/glow) dan wajib punya varian `prefers-reduced-motion`.

## 2. Tech stack

- Framework: Next.js (App Router) + TypeScript
- Styling: Tailwind v4 (token di `app/globals.css` blok `@theme`, TIDAK ada tailwind.config.js)
- Layer AI/chat: Vercel AI SDK (streaming + tool calling + generative UI)
- LLM: via API (Claude / OpenAI / Gemini / Groq)

- Rate limiting: Upstash

## 3. Batasan (hard constraints)

- Sudut SIKU (0px) secara default. Lengkung hanya lewat `rounded-full` untuk elemen yang bentuk aslinya lingkaran. Jangan tambah radius kecil ke bar/kartu/blok.
- Tanpa gradient, drop shadow blur, atau glow. Kedalaman = offset blok solid (hard shadow tanpa blur).
- Background full-bleed HANYA dari token background (lihat §5). Warna aset tidak boleh jadi background halaman.
- Jangan hardcode hex di komponen — selalu pakai kelas token Tailwind (`bg-brick`, `text-coral`).
- Chatbot tidak boleh mengarang fakta: jawab hanya dari konteks retrieval; di luar konteks katakan tidak tahu.
- URL aset (CV, LinkedIn) di-hardcode dari sisi server, bukan dihasilkan model.
- Selalu hormati `prefers-reduced-motion`. Jangan pakai easing lembut/linear (bikin mood jatuh jadi "soft") — pakai `--ease-retro-bounce`.
- Jangan tiru persis karya referensi (title sequence START-UP berhak cipta). Tangkap bahasa visualnya sebagai karya orisinal.

## 4. Estetika: flat retro

Bergaya title sequence flat-retro (rujukan mood: START-UP main title). Blok warna solid, bentuk geometris tegas, kontras figure-ground kuat di atas dark/cream base. Kesan ceria-energetik datang dari BENTUK TEGAS + WARNA, bukan dari efek halus atau warna neon. Default gelap; cream untuk adegan terang.

### Pembagian aset: dibuat via kode vs disiapkan pemilik

Aset kompleks (ilustrasi bespoke) disiapkan pemilik sebagai file, JANGAN dikode: ilustrasi karakter/figur, cityscape penuh, adegan teater/sirkuit/perspektif yang detail, grid ikon aplikasi. Ini diletakkan di `public/lottie/` (animasi) atau `public/illustrations/` (SVG/PNG statis), lalu dipanggil lewat komponen wrapper di `components/scenes/`.

Aset minor umum dibuat via kode (murni CSS/SVG, bentuk geometris sederhana): semua komponen di `components/retro/`, semua primitif di `components/ui/`, dan bentuk dekoratif kecil (bar, kartu split, heksagon, garis diagonal, frame). Panduan detailnya ada di §6a.

## 6a. Spesifikasi desain tiap komponen

Aturan yang berlaku untuk SEMUA komponen di bawah: sudut siku (0px) kecuali disebut lingkaran; tanpa gradient/shadow blur/glow; warna hanya dari token (§5); kedalaman lewat offset blok solid (mis. `translate` + blok warna di belakang), bukan bayangan lembut; teks memakai `text-on-dark`/`text-on-light` sesuai mode.

### Komponen retro (components/retro/)

`ColorBlockBar` — bar horizontal warna solid diakhiri kotak (tile) ikon berwarna kontras. Bentuk: persegi panjang siku, tinggi ~36-40px, tile bujur sangkar seukuran tinggi bar. Warna bar `slate`/`brick`/`mustard`; tile `pine` atau `cream-shape` dengan ikon di tengah. Ikon dari Phosphor/Iconoir (amplop, gambar). Props: `barColor`, `tileColor`, `icon`, `width`. Dipakai sebagai list item, label, atau elemen dekoratif hero.

`SplitCard` — kartu persegi dibagi diagonal jadi dua warna via `clip-path` (segitiga di atas segitiga). Bentuk: bujur sangkar/persegi siku, ~120-140px. Pasangan warna: `slate`+`pine`, `pine`+`coral`, `plum`+`teal-dark`. Props: `colorA`, `colorB`, `size`, opsional `label`. Dipakai sebagai kartu kategori/tag proyek.

`HexGrid` — kluster heksagon flat-top rapat (pola honeycomb). Bentuk: heksagon via `clip-path` polygon, tanpa radius. Warna selang-seling `pine`/`mustard`/`cream-shape`/`brick`, dengan satu heksagon `red` sebagai titik fokus. Props: `rows`, `cols`, `highlightIndex`. Dipakai sebagai lantai/alas dekoratif di bagian bawah section.

`SeatGrid` — grid rapat blok kecil berulang menyerupai kursi (blok badan + blok sandaran kecil di atasnya). Warna selang-seling `coral`/`purple`/`pine`/`mustard`. Props: `rows`, `cols`, `gap`. Dekoratif; kepadatan yang menciptakan tekstur, jadi jaga jarak antar-blok kecil dan konsisten.

`PerspectiveScene` — garis/bidang konvergen ke satu titik tengah untuk ilusi kedalaman. Bentuk: beberapa trapesium/garis yang menyempit ke tengah. Dinding `pine`, garis `mustard`/`red`/`slate`. Props: `vanishingPoint` (default tengah), `lineColors`. Wrapper kosong yang mengandalkan animasi manual untuk efek "maju".

`DiagonalStripes` — strip diagonal sejajar di atas latar gelap. Bentuk: garis miring ~45°, ketebalan seragam, jarak seragam. Warna `red`/`brick` atau `mustard` tunggal. Props: `color`, `angle`, `thickness`, `gap`. Dipakai sebagai pengisi latar section atau transisi.

`PreviewCard` — kartu kecil menyerupai preview email/media. Bentuk: persegi siku warna `offwhite`, berisi mini-ilustrasi geometris (beberapa segitiga warna sebagai "gunung", garis tipis sebagai "teks"). Warna isi `slate`/`pine`/`brick`. Props: `title`, opsional `thumbnail`. Ini aset minor yang boleh dibuat via kode (SVG sederhana).

`NestedFrame` — bingkai persegi kosong di dalam bingkai (outline bertingkat), satu bingkai `frame-green` menandai fokus/terpilih. Bentuk: hanya border siku (tanpa isi), ketebalan tipis (~1-2px). Outline luar `text-on-dark`, bingkai fokus `frame-green`. Props: `levels`, `focusLevel`, `children`. Dipakai membingkai konten yang sedang disorot.

`KineticHeading` — judul dengan tiap huruf berwarna berbeda dan reveal berjenjang. Bentuk: teks besar `font-display`, bobot tebal, tiap huruf `<span>` sendiri. Warna disikluskan `coral`/`mustard`/`pine`/`slate`/`brick`. Props: `text`, opsional `underline` (garis coretan SVG). Animasi manual: stagger per huruf, easing `--ease-retro-bounce`.

### Primitif UI (components/ui/)

Semua primitif bersudut siku, flat, tanpa bayangan lembut. Kedalaman/penekanan lewat offset blok solid.

`Button` — persegi siku, padding ~12px 20px, `font-display` atau `font-sans` tebal. Varian: primary = isi `brick` (atau `pine`) dengan teks `cream-shape`; secondary = latar transparan dengan border tegas 1.5-2px warna aset + teks warna sama; pressed/hover = geser 2px + blok offset solid di belakang untuk kesan "ditekan". Ikon opsional di kiri/kanan (Phosphor/Iconoir). Jangan pakai radius, jangan pakai shadow blur.

`Badge` / `Pill` — label kecil. Badge = persegi siku isi warna aset + teks kontras (mode-aware). Pill = satu-satunya yang boleh `rounded-full`, dipakai untuk status/tag ringan. Padding ~4px 10px, `font-mono` kecil untuk kesan teknikal.

`Card` — kontainer konten siku, latar `ink-panel` (gelap) / `cream-raised` (terang), border tipis opsional 0.5-1px. Aksen bisa lewat satu sisi border tebal warna aset (ingat: border satu sisi = radius 0). Tanpa bayangan lembut.

`Input` / `TextField` — kotak siku, border tegas 1.5px warna netral, fokus = border berganti ke `frame-green` atau `blue`. Latar `ink-panel`/`cream-raised`. Untuk input chat, boleh lebih tinggi dengan ikon kirim di kanan.

`IconButton` — bujur sangkar siku berisi satu ikon; hover = isi warna aset tipis. Untuk aksi tunggal (kirim pesan, tutup, menu).

`Divider` — garis tipis 0.5-1px warna `text` dengan opasitas rendah, atau blok warna aset tipis sebagai pemisah bergaya.

Panduan ikon: gunakan Phosphor atau Iconoir (garis flat berkarakter), ukuran 16-20px inline, 24px dekoratif. Konsisten satu set di seluruh proyek.

## 7. Dokumentasi LLM / RAG

### Konsep inti

Sistem ini RAG (Retrieval-Augmented Generation), BUKAN fine-tuning. Tidak ada training model, tidak butuh PyTorch. LLM dipakai via API. Yang dibangun ada dua: pipeline retrieval (menyusun konteks untuk jawaban) dan lapisan tool (memberi model kemampuan bertindak di UI). Model hanya MEMILIH tool + argumen; eksekusi dan data selalu berada di sisi kita.

### Strategi dua fase

Fase 1 (sekarang): seluruh knowledge base dijejalkan ke system prompt. Data kecil, muat di context window besar, tanpa vector DB. Katalog proyek & skill hidup sebagai list statis di `lib/tools/portfolio-data.ts`.

Fase 2 (upgrade): pindah ke RAG sungguhan. Persiapan (sekali / saat data berubah): data diri -> chunking (potong per topik) -> embedding (ubah tiap chunk jadi vektor) -> simpan ke vector DB. Saat pengunjung bertanya: pertanyaan -> embed -> cari chunk relevan -> susun prompt (system + konteks + pertanyaan) -> LLM -> stream jawaban. Yang penting: hanya isi `lib/rag/` dan accessor di `portfolio-data.ts` yang berubah; definisi tool dan kartu UI tidak tersentuh (ini penerapan dependency inversion secara nyata).

### Model tool: dua kelompok

Tool dibagi menurut SIAPA yang mengeksekusi. Ini keputusan arsitektur inti dan menentukan apakah sebuah tool punya fungsi `execute`. Karena chatbot mengendalikan seluruh situs (§1a), `navigateToPage` adalah aksi kontrol utamanya.

Kelompok A — client-forwarded (TANPA `execute`). Di AI SDK, tool tanpa `execute` tidak dijalankan di server; call-nya diteruskan ke client, dan komponen React yang menjalankan aksinya. Dipakai untuk aksi yang hanya bisa terjadi di browser (pindah route, scroll). Modul: `lib/tools/navigation-tools.ts`. Eksekusinya di client hidup di `components/chat/useToolActions.ts`.

- `navigateToPage` — pindah ke halaman konten (`/about`, `/projects`, dst) atau kembali ke landing `/`.
- `scrollToSection` — smooth scroll ke section pada halaman konten yang sedang aktif.
- `highlightSection` — sorot section sesaat (sering dipasangkan dengan scroll; pakai `NestedFrame`/`frame-green`).
- `openProjectDetail` — buka halaman detail proyek (route diturunkan dari id di client).

Kelompok B — server-executed (DENGAN `execute`). Berjalan di server karena butuh URL asli atau data katalog. `execute` tidak menaruh URL secara inline melainkan mendelegasikan ke lapisan data (`portfolio-data.ts`), sehingga URL rahasia terpusat & teraudit dan tak pernah masuk prompt LLM. Modul: `lib/tools/resource-tools.ts` dan `lib/tools/content-tools.ts`.

- `showDownloadCard` — kembalikan nama file + URL CV untuk kartu unduhan.
- `openGithub` / `openLinkedin` — kembalikan URL sosial; client yang melakukan `window.open`.
- `openProjectDemo` — kembalikan URL demo (atau tanda "tidak ada demo publik").
- `showContactCard` — kembalikan email + link sosial + link penjadwalan.
- `filterProjects` — kembalikan project cards, opsional difilter per tag (mis. "proyek AI").
- `filterSkills` — kembalikan skill untuk skill grid, opsional per kategori.

### Batas modul (lib/tools/)

- `types.ts` — identifier bersama (page, section, project, skill). Sumber tunggal agar schema tool, server, dan komponen UI tidak lepas sinkron. Nilainya mengikuti §1a.
- `portfolio-data.ts` — ditandai `server-only`. Memegang katalog konten + membaca URL aset dari `lib/config/links.ts`. Di Fase 2 isinya berubah jadi query retrieval, tapi tanda tangan fungsinya tetap.
- `navigation-tools.ts` / `resource-tools.ts` / `content-tools.ts` — definisi tool per kelompok.
- `index.ts` — merakit semua jadi `portfolioTools` dan menurunkan tipe `PortfolioUIMessage` (via `InferUITools`) untuk type-safety server->client.

### Generative UI

Jawaban model tidak selalu teks. Hasil tool Kelompok B dirender jadi komponen (`CvCard`, `ContactCard`, Project Cards, Skill Grid) di `components/chat/tool-cards/`, bukan link mentah — tampil di permukaan chat (landing) atau di panel chat (halaman konten). Chatbot tidak "mengirim file"; ia memicu UI yang menampilkan tombol ke file statis di `public/`.

### Pengaman (guardrail)

System prompt tegas anti-halusinasi ("jawab hanya dari konteks; kalau tidak ada, katakan tidak tahu"). URL aset selalu dari server (Kelompok B / `portfolio-data.ts`), tidak pernah dikarang model. Rate limiting per pengunjung (Upstash). Batasi panjang input & jumlah pesan per sesi. Jangan pernah ekspos API key ke client.

## 7a. Alur chatbot

Alur satu putaran, dari pesan pengunjung sampai UI berubah:

1. Pengunjung mengetik di `ChatWidget` (permukaan chat full-screen di `/`, atau panel chat di halaman konten) lalu mengirim.
2. Client melakukan POST ke `app/api/chat/route.ts` membawa riwayat pesan.
3. Server menyusun konteks: Fase 1 menempelkan seluruh knowledge ke system prompt; Fase 2 melakukan retrieval dulu lalu menempelkan chunk relevan. System prompt anti-halusinasi ikut dipasang di sini.
4. Server memanggil `streamText` dengan `portfolioTools` dan `stopWhen: stepCountIs(...)`, agar model bisa memanggil beberapa tool berurutan lalu menutup dengan teks.
5. Model memilih SATU dari dua jalur:
   - Jawaban teks -> di-stream langsung ke gelembung chat.
   - Tool call -> bercabang menurut kelompok tool:
     - Kelompok A (tanpa `execute`) -> call diteruskan ke client -> `useToolActions` menjalankan `router.push` / `scrollIntoView` / highlight.
     - Kelompok B (dengan `execute`) -> server menjalankan, mengambil URL/data aman dari `portfolio-data.ts`, lalu mengirim hasil -> client merender kartu (tool-cards) atau membuka link.
6. Hasil tool dikembalikan ke model oleh AI SDK; karena `stopWhen`, model dapat menutup dengan kalimat teks (mis. "CV-nya sudah saya siapkan di bawah"). Putaran selesai.

Contoh multi-step: "show your skills" -> model memanggil `navigateToPage('/about')` lalu `scrollToSection('about-skills')` (dua tool Kelompok A berurutan, dijalankan client karena landing bukan halaman scroll), lalu menutup dengan teks singkat.

Prinsip yang dijaga sepanjang alur: model hanya memilih tool + argumen; semua efek nyata (navigasi, URL, data) terjadi di client atau server, bukan di dalam model. Ini yang membuat sistem aman sekaligus anti-halusinasi, dan menjaga dua interface (chat + konten tradisional) berbagi route & section id yang sama seperti di §1a.

### Konvensi kode

- Satu komponen per file, named export, PascalCase.
- Komponen `retro/` harus stateless & presentational — terima warna/isi via props, jangan pernah hardcode.
- Logika RAG hanya di `lib/rag/` — komponen chat tidak berisi logika retrieval.
- URL aset hanya dari `lib/config/links.ts`.
- Token warna/radius hanya dari `app/globals.css` — jangan pernah duplikasi nilai hex di tempat lain.
- Identifier lintas-potong yang dipakai bersama (section id, route, project/skill id) hanya dari `lib/tools/types.ts` — ini menjaga schema tool, route chat, dan komponen halaman tetap sinkron seiring situs membesar.

## 9. Gaya kode pemilik (wajib diikuti)

- SOLID. Satu tanggung jawab per unit, dependency lewat abstraksi, komponen kecil & fokus.
- Identifier bahasa Inggris. Semua nama folder/file/variabel/fungsi/tipe memakai istilah bahasa Inggris. Prosa/komentar penjelas boleh Indonesia, tapi identifier selalu Inggris.
- Tanpa nested/helper function di dalam file. Fungsi untuk tugas baru tidak boleh didefinisikan di dalam file yang memanggilnya — termasuk untuk dipakai fungsi lain di file yang sama. Pisahkan ke file/modul sendiri lalu import. Alasan: file dengan banyak fungsi bertumpuk sangat sulit dibaca; satu file idealnya satu unit tugas.
- Komentar dalam kalimat deskriptif/pasif, bukan imperatif. Jelaskan "ini untuk apa", bukan memerintah. Disukai: "fungsi ini digunakan untuk mengambil chunk relevan." Dihindari: "ambil chunk relevan."
- Dokumentasi langkah berikutnya wajib. Di akhir setiap unit kerja yang belum selesai, tulis apa yang sudah selesai, apa yang belum, dan langkah konkret berikutnya — entah di blok komentar bawah file terkait, atau di `NEXT_STEPS.md`. Ini menjaga konteks di antara jeda/lanjut pemilik yang sering — cek `NEXT_STEPS.md` lebih dulu saat melanjutkan pekerjaan.

## 10. Catatan belajar

Prioritas belajar utama pemilik adalah implementasi LLM. Untuk semua pekerjaan di `lib/rag/` dan `app/api/chat/`, sertakan penjelasan yang mendidik: alasan di balik tiap keputusan, trade-off yang ada, dan bagaimana bagian-bagian saling terhubung — bukan sekadar kode jadi tanpa konteks. Pekerjaan visual/frontend boleh lebih ringkas.

## 11. Aturan motion — "Cinematic Startup Motion"

Rujukan rasa: opening title K-drama startup (mis. START-UP, Search: WWW) — energetik, modern, confident, clean, whitespace lega, transisi cepat. Hasilnya harus terbaca sebagai "engineer ini paham desain", bukan "engineer ini baru menemukan Framer Motion". Library: Framer Motion, dipusatkan lewat `components/motion/motionConfig.ts`.

Prinsip inti: motion memberi fokus, bukan menjadi fokus. Tiap gerakan butuh alasan — memperkenalkan elemen, memberi umpan balik interaksi, atau mengarahkan perhatian. Gerakan terasa cepat, presisi, percaya diri, tidak pamer. Kalau sebuah animasi tidak melayani salah satu dari tiga alasan itu, jangan dipakai.

Teknik: fade + translate sebagai entrance default (opacity 0 + geser ~8-16px) hampir di tiap elemen; stagger untuk daftar card/skill/project; micro-interaction hover (scale ~1.02, lift 2-4px, atau perubahan warna border/outline — jangan glow lembut); scroll reveal konsisten per section; parallax ringan hanya pada bentuk dekoratif, jangan pada teks konten; gerakan ambient latar sangat lambat boleh, tapi lewat pergeseran blok/bentuk warna solid, bukan gradient.

Durasi & easing: entrance ~200-400ms, hover ~120-200ms — cepat dan tajam. Pakai kurva ease-out yang percaya diri (`FUNCTIONAL_EASE` di `motionConfig.ts`) untuk gerakan fungsional. `--ease-retro-bounce` / `RETRO_BOUNCE_EASE` dicadangkan untuk aksen playful terbatas (mis. huruf `KineticHeading`), BUKAN UI umum — pantulan berlebihan bertentangan dengan rasa "confident/clean". Jarak stagger ~40-80ms.

Larangan: tanpa bounce berlebihan, flip, spin, atau zoom besar; tanpa gradient (termasuk "gradient ambient bergerak" — bertentangan dengan §4); tanpa glassmorphism atau glow/soft shadow (bertentangan dengan estetika flat-siku di §4-§6) — kedalaman & penekanan selalu dari offset blok solid dan perubahan border. Selalu hormati `prefers-reduced-motion` dengan varian tanpa gerak (konten langsung tampil).

Loading screen (intro): `IntroSequence` menjalankan intro dua fase saat load awal — Fase 1 `LoadingScreen` (frasa sapaan berganti), Fase 2 `BrandReveal` (wordmark + tombol continue) — ditutup transisi wipe blok solid. Perpindahan fase digerakkan oleh selesainya animasi tiap fase (via `advancePhase()`), bukan timer tetap — lihat `lib/intro/useIntroSequence.ts`. Karakter: singkat dan tegas, keluar seperti potongan film (fade + translate) menuju konten. Progress ditunjukkan lewat pertumbuhan blok solid, bukan lingkaran berputar.

Animasi signature "wah": satu gerakan andalan yang boleh lebih ekspresif dari micro-interaction biasa, misalnya color-block reveal atau wipe `clip-path`. Gunakan hanya pada momen penting seperti intro, transisi interface, atau kemunculan tool-card utama; jangan mengulangnya di setiap elemen. Tetap sediakan varian tanpa gerak untuk `prefers-reduced-motion`.

export async function POST(request: Request) {
  const {
    messages,
  }: {
    messages: UIMessage[];
  } = await request.json();

  const latestUserText =
    getLatestUserText(messages);

  const resourceToolChoice =
    getResourceToolChoice(
      latestUserText
    );

  if (
    resourceToolChoice?.toolName ===
    "showDownloadCard"
  ) {
    if (
      process.env.NODE_ENV ===
      "development"
    ) {
      console.log(
        "Portfolio deterministic resource:",
        {
          latestUserText,
          resourceToolChoice,
        }
      );
    }

    return createShowDownloadCardResponse(
      messages
    );
  }
  if (resourceToolChoice?.toolName === "showContactCard") {
    return createContactCardResponse(messages);
  }
  if (
    resourceToolChoice?.toolName ===
    "openGithub"
  ) {
    if (
      process.env.NODE_ENV ===
      "development"
    ) {
      console.log(
        "Portfolio deterministic resource:",
        {
          latestUserText,
          resourceToolChoice,
        }
      );
    }

    return createExternalResourceResponse({
      messages,
      output:
        getOpenGithubOutput(),
    });
  }
  if (
    resourceToolChoice?.toolName ===
    "openLinkedin"
  ) {
    if (
      process.env.NODE_ENV ===
      "development"
    ) {
      console.log(
        "Portfolio deterministic resource:",
        {
          latestUserText,
          resourceToolChoice,
        }
      );
    }

    return createExternalResourceResponse({
      messages,
      output:
        getOpenLinkedinOutput(),
    });
  }
  const contentToolChoice =
    getContentToolChoice(
      latestUserText
    );

  if (
    contentToolChoice?.toolName ===
    "filterProjects"
  ) {
    if (
      process.env.NODE_ENV ===
      "development"
    ) {
      console.log(
        "Portfolio deterministic content:",
        {
          latestUserText,
          contentToolChoice,
        }
      );
    }

    return createProjectFilterResponse({
      messages,
      userText:
        latestUserText,
    });

  }
  if (
    contentToolChoice?.toolName ===
    "filterSkills"
  ) {
    if (
      process.env.NODE_ENV ===
      "development"
    ) {
      console.log(
        "Portfolio deterministic content:",
        {
          latestUserText,
          contentToolChoice,
        }
      );
    }

    return createSkillFilterResponse({
      messages,
      userText:
        latestUserText,
    });
  }
  const navigationAction =
    getDeterministicNavigationAction(
      latestUserText
    );

  if (navigationAction) {
    if (
      process.env.NODE_ENV ===
      "development"
    ) {
      console.log(
        "Portfolio deterministic navigation:",
        {
          latestUserText,
          navigationAction,
        }
      );
    }

      createUIMessageStream({

        execute: ({ writer }) => {

    return createUIMessageStreamResponse({

    });

          latestUserText,
          unknownProjectEntity,

      );

    return createUnknownProjectResponse({

    getSkillKnowledge(
      latestUserText
    );

  if (skillKnowledge) {
    if (
      process.env.NODE_ENV ===
      "development"
    ) {
      console.log(
        "Portfolio skill knowledge:",
        {
          latestUserText,
          skillKnowledge,
        }
      );
    }

    return createSkillKnowledgeResponse({
      messages,
      result:
        skillKnowledge,
    });
  }
  const employmentKnowledge =
    getEmploymentKnowledge(
      latestUserText
    );

  if (employmentKnowledge) {
    if (
      process.env.NODE_ENV ===
      "development"
    ) {
      console.log(
        "Portfolio employment knowledge:",
        {
          latestUserText,
          employmentKnowledge,
        }
      );
    }

    return createEmploymentKnowledgeResponse({
      messages,
      result:
        employmentKnowledge,
    });
  }

  const unknownCertificationEntity =
    getUnknownCertificationEntity(
      latestUserText
    );

  if (unknownCertificationEntity) {
    if (
      process.env.NODE_ENV ===
      "development"
    ) {
      console.log(
        "Portfolio unknown certification:",
        {
          latestUserText,
          unknownCertificationEntity,
        }
      );
    }

    return createUnknownCertificationResponse({
      messages,
      certificationName:
        unknownCertificationEntity
          .certificationName,
    });
  }
  if (
    isAiExperienceDurationQuery(
      latestUserText
    )
  ) {
    if (
      process.env.NODE_ENV ===
      "development"
    ) {
      console.log(
        "Portfolio AI experience duration:",
        {
          latestUserText,
        }
      );
    }

    return createAiExperienceDurationResponse({
      messages,
    });
  }
  const portfolioToolChoice =
    getNavigationToolChoice(
      latestUserText
    );

  const portfolioTools =
    createPortfolioTools();

  if (
    process.env.NODE_ENV ===
    "development"
  ) {
    console.log(
      "Portfolio tool routing:",
      {
        latestUserText,
        portfolioToolChoice,
      }
    );
  }
  const result = streamText({
    model: getChatModel(),
    instructions: buildSystemPrompt(),

    messages: await convertToModelMessages(
      messages,
      {
        tools: portfolioTools,

        /*
         * Safety net agar satu tool call rusak tidak
         * mengunci seluruh percakapan berikutnya.
         */
        ignoreIncompleteToolCalls: true,
      }
    ),

    tools: portfolioTools,

    activeTools: [
      "navigateToPage",
      "scrollToSection",
      "highlightSection",
      "openProjectDetail",
      "showDownloadCard",
      "openGithub",
      "openLinkedin",
      "showContactCard",
      "filterProjects",
      "filterSkills",
    ],
    toolChoice: portfolioToolChoice,

    onStepFinish: ({
      text,
      toolCalls,
      toolResults,
      finishReason,
    }) => {
      if (
        process.env.NODE_ENV !==
        "development"
      ) {
        return;
      }

      console.log(
        "Portfolio AI step:",
        JSON.stringify(
          {
            text,
            toolCalls,
            toolResults,
            finishReason,
          },
          null,
          2
        )
      );
    },
    onError: ({ error }) => {
      console.error(
        "streamText gagal:",
        error
      );
    },
  });

  return result.toUIMessageStreamResponse({
    originalMessages: messages,

    onError: (error) => {
      console.error(
        "Stream error diteruskan ke client:",
        error
      );

      return "Asisten AI sedang tidak bisa dihubungi. Coba lagi sebentar lagi.";
    },
  });

        <ChatMessageBubble
          role={message.role}
        >
          {messageText}
        </ChatMessageBubble>
      ) : null}

      {message.role === "assistant"
        ? portfolioKnowledgeDataParts.map(
          (part, index) => (
            <ChatMessageBubble
              key={
                part.id ??
                `portfolio-knowledge-${index}`
              }
              role="assistant"
            >
              {part.data.message}
            </ChatMessageBubble>
          )
        )
        : null}
      {message.role === "assistant"
        ? evaluationResultParts.map(
          (part, index) => (
            <EvaluationDataRenderer
              key={
                part.id ??
                `evaluation-${index}`
              }
              part={part}
            />
          )
        )
        : null}

      {message.role === "assistant"
        ? evaluationErrorParts.map(
          (part, index) => (
            <ChatMessageBubble
              key={
                part.id ??
                `evaluation-error-${index}`
              }
              role="assistant"
            >
              {part.data.message}
            </ChatMessageBubble>
          )
        )
        : null}
        
      {message.role === "assistant"
        ? navigationActionParts.map(
          (part, index) => (
            <ChatMessageBubble
              key={
                part.id ??
                `navigation-action-${index}`
              }
              role="assistant"
            >
              {part.data.message}
            </ChatMessageBubble>
          )
        )
        : null}

      {message.role === "assistant"
        ? navigationToolParts.map(
          (part) => (
            <NavigationToolStatus
              key={part.toolCallId}
              part={part}
            />
          )
        )
        : null}

      {message.role === "assistant"
        ? downloadCardParts.map(
          (part) => (
            <ShowDownloadCardRenderer
              key={part.toolCallId}
              part={part}
            />
          )
        )
        : null}

      {message.role === "assistant"
        ? cvDownloadDataParts.map(
          (part, index) => (
            <CvDownloadDataRenderer
              key={
                part.id ??
                `cv-download-${index}`
              }
              part={part}
            />
          )
        )
        : null}
      {message.role === "assistant"
        ? externalResourceToolParts.map(
          (part) => (
            <ExternalResourceToolRenderer
              key={part.toolCallId}
              part={part}
            />
          )
        )
        : null}

      {message.role === "assistant"
        ? externalResourceDataParts.map(
          (part, index) => (
            <ExternalResourceDataRenderer
              key={
                part.id ??
                `external-resource-${index}`
              }
              part={part}
            />
          )
        )
        : null}
      {message.role === "assistant" ? contactCardToolParts.map((part) => <ContactCardToolRenderer key={part.toolCallId} part={part} />) : null}
      {message.role === "assistant" ? contactCardParts.map((part, index) => <ContactCardResult key={part.id ?? `contact-${index}`} value={part.data} />) : null}
      {message.role === "assistant"
        ? projectFilterToolParts.map(
          (part) => (
            <ProjectFilterToolRenderer
              key={part.toolCallId}
              part={part}
            />
          )
        )
        : null}

      {message.role === "assistant"
        ? projectFilterDataParts.map(
          (part, index) => (
            <ProjectFilterDataRenderer
              key={
                part.id ??
                `project-filter-${index}`
              }
              part={part}
            />
          )
        )
        : null}

      {message.role === "assistant"
        ? projectFilterErrorParts.map(
          (part, index) => (
            <ProjectFilterErrorRenderer
              key={
                part.id ??
                `project-filter-error-${index}`
              }
              part={part}
            />
          )
        )
        : null}
      {message.role === "assistant"
        ? skillFilterToolParts.map(
          (part) => (
            <SkillFilterToolRenderer
              key={part.toolCallId}
              part={part}
            />
          )
        )
        : null}

      {message.role === "assistant"
        ? skillFilterDataParts.map(
          (part, index) => (
            <SkillFilterDataRenderer
              key={
                part.id ??
                `skill-filter-${index}`
              }
              part={part}
            />
          )
        )
        : null}

      {message.role === "assistant"
        ? skillFilterErrorParts.map(
          (part, index) => (
            <SkillFilterErrorRenderer
              key={
                part.id ??
                `skill-filter-error-${index}`
              }
              part={part}
            />
          )
        )
        : null}
    </article>
  );
}
